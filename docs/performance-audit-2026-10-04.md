# Kanban 性能测试与优化点 · 2026-10-04

**主要瓶颈是有数据变化时的前端全量重绘，优先优化时间格式化，其次减少 DOM 重建。** 当前约 50 条任务时没有测到明显规模瓶颈；200 条开始出现约 50 ms 的同步渲染，1,000 条达到约 247 ms。无变化刷新已经跳过重绘，应该保留这一机制。本轮增加性能基准与测试说明，没有修改业务逻辑或安装插件。

## 1. 测试条件与边界

**这些数据是同机基线和隔离实验，不能直接替代原生侧栏的端到端体验。** 仓库版本 0.4.51，基线提交 `85dce3ffcf27136c5a8c34f7e77e9a1f2be27af3`；Apple M1 Max / macOS arm64 / Node v22.23.1 / Chromium 145.0.7632.6。

- **前端**：正式构建的 MCP UI、真实 MCP SDK 宿主桥接、1440 × 900 窗口；50 / 200 / 1,000 条合成任务，每项预热 3 次、采样 15 次，报告 p50 / p95。1,000 条另测正常动画偏好。
- **样本分布**：一个 Ungrouped 任务，其余集中在 For Later，属于单组大量任务场景。包含项目、未读、摘要、时间和操作入口；没有覆盖大量运行中动画、复杂 PR 徽章、多主机和长文本混合负载。
- **计时口径**：同步操作加强制布局，随后等待两帧。单任务变化和无变化刷新包含测试输入的克隆成本。p95 在 15 个样本下接近最大值，应关注趋势而非小数差异。
- **后端模拟**：四组任务、真实 metadata 组装和 runtime 批处理代码；RPC 人为设置 0 / 5 / 20 ms 延迟。模拟数值只用于展示增长关系。
- **真实只读核查**：本机元数据和 Desktop runtime 各读取 5 次，只保存数量、耗时和覆盖信息，不保存任务标题、摘要或原始返回值；这些是小样本核查，未包含 Git/GitHub enrichment，runtime 核查与回归测试并发运行。
- **资源**：构建后的 MCP HTML 为 672,970 字节。局部加载时间和 SDK 开销未独立剖析，不能据此认定 bundle 是主瓶颈。

## 2. 测量结果

**单条变化与完整重绘成本相近，无变化刷新则明显便宜。** 下表单位为 ms，单元格为 p50 / p95，默认减少动态效果。

| 操作 | 50 条 | 200 条 | 1,000 条 |
| --- | ---: | ---: | ---: |
| Board 完整渲染 | 13.5 / 14.6 | 48.7 / 60.6 | 246.9 / 315.0 |
| List 完整渲染 | 13.7 / 14.4 | 48.9 / 54.0 | 244.7 / 284.2 |
| 单任务标题变化 | 13.3 / 17.0 | 49.5 / 62.8 | 241.9 / 299.6 |
| 无变化刷新 | 0.6 / 0.7 | 1.4 / 1.5 | 5.2 / 5.9 |
| 搜索命中大部分任务 | 12.8 / 17.1 | 47.4 / 50.9 | 246.4 / 320.0 |
| 大组折叠后渲染 | 8.2 / 8.9 | 28.6 / 31.9 | 132.7 / 198.2 |
| 临时复用 formatter 后 Board 渲染 | 8.6 / 10.8 | 29.7 / 34.6 | 153.2 / 291.3 |

**正常动画偏好没有改变全量重建这一主要瓶颈。** 1,000 条任务下 Board 渲染 p50 为 229.1 ms，单任务变化为 251.0 ms，无变化刷新为 5.0 ms。隔离实验中的任务未处于 running 状态，因此这不证明大量旋转动画的性能。

**真实本机后端读取很快，但逐任务 runtime RPC 有明确的规模成本。** 本机看板共 55 条任务，元数据读取 p50 为 12.8 ms，范围 10.7–28.2 ms，首次 reader 初始化另需 57.6 ms；Desktop runtime 读取 p50 为 12.9 ms，范围 12.5–18.1 ms，50 条任务获得实时状态。其余任务未被此测量认定为 idle 或完成。

| --- | ---: | ---: | ---: |
| 模拟元数据纯组装 p50 | 0.19 ms | 1.18 ms | 21.51 ms |
| 元数据 RPC 次数 | 7 | 7 | 15 |
| runtime thread/read 次数 | 50 | 200 | 1,000 |

## 3. 优化优先级与功能保护

**时间格式化是收益已经验证、改动范围最小的首选。** `ui.html:1029` 每次调用都创建 `Intl.DateTimeFormat`，`ui.html:1231` 每张卡片重复调用三次。1,000 条任务的纯时间格式化 p50 为 83.4 ms，复用同配置 formatter 后为 1.8 ms；整板渲染对照降低约 38%。对照只临时替换隔离页面函数，已经核对时间文本、tooltip 和 aria-label 完全一致，尚未落地优化。对照不是随机交错的 A/B，尾延迟存在 GC 等噪声，需在实际改动后重测。

| 优先级 | 优化点与方案 | 必须保护的行为 |
| --- | --- | --- |
| P1 | 复用一个固定 locale / timezone 的 formatter；每张卡片只格式化一次时间，复用到文本和属性 | Asia/Shanghai、en-US、24 小时制、Unknown time；文本、tooltip、aria-label 和时间点击导航一致 |
| P2 | `render()` 按 taskKey 更新变化卡片，或先只更新受影响组；保留全量 render 作为简单 fallback | Board/List、手动任务和组排序、项目继承、未读和 runtime 变化、焦点、滚动、动画衔接、菜单和草稿保护；操作回读仍权威 |
| P2 | 折叠组延后创建卡片；先优化折叠状态，不急于引入虚拟列表 | 折叠时跨组 drop 仍能接收且展开；计数和排序使用完整数据；展开恢复滚动、项目视图和导航 |
| P3 | 大规模 runtime 改为事件失效、增量读取和有界补偿；结合实际慢 RPC 再决定是否实施 | 15 秒 freshness、未知状态、waiting flags、断连恢复、失败不续期；不靠扩大并发掩盖负载 |
| P3 | `build.mjs` 的 membership 建立 memberKey → sections 反向索引，减少逐任务 `includes` 扫描 | 保留多个匹配的计数和歧义处理，以及 direct / pinned / verifiedAlias / project 的优先级；不得凭 cwd 推断项目 |

**折叠只是减少布局，并未减少卡片创建。** 1,000 条任务时折叠前后看板后代节点都为 24,631；折叠重绘仍需约 133 ms。这支持延迟创建折叠卡片，但不能用删除数据替代隐藏内容。

**无变化刷新和读取限流已经有效，不应在优化中丢失。** 性能脚本确认相同看板应用后 card DOM 引用保持；runtime 模拟延迟场景最多 4 个 thread/read 并发，每批最多 100 个 ID。当前 3 秒轮询会在读取未完成时跳过，不能把 5.3 秒模拟读取描述成每 3 秒必定完成的刷新。

## 4. 回归验证与复现

**已有功能通过自动化回归，优化方案尚未成为业务改动。** 本轮修改仅涉及性能脚本、npm 入口、测试说明、忽略本机结果和本报告；不能将隔离对照的收益称为已安装版本的性能提升。

- Node 全量：`npm test`，656 项通过，0 失败。
- Flow 单独核查：`node --test flow/tests/*.test.mjs`，179 项通过；其中用例也被根级 Flow 测试导入，不与 656 相加。
- Chromium 交互：11 项通过，覆盖 Board/List 跨组拖动、折叠 Ungrouped、项目继承、断连恢复、冲突回读、排序重载保持和 Escape 取消。默认端口曾被占用，改用临时配置的独立端口 19843，测试文件及正式配置未改动。
- 原生协议隔离实验：`npm run test:integration` 通过；真实 bundled App Server、一次性 CODEX_HOME、模拟 Desktop MCP，覆盖重命名、项目修改/清除、分组、Pin/Unpin、Archive/Undo、创建去重、自动分类初始化等，modelTurnsStarted = 0。
- 性能断言：四组前端场景全部通过；任务数量、无变化 DOM、时间输出、运行状态覆盖及并发约束、无页面异常、无 fixture 移动/归档/导航均通过。
- 实际原生侧栏视觉验收、长时间 heap / GC 趋势、慢 GitHub 和多窗口同时轮询尚未覆盖。

```sh
npm ci
npm run test:performance
npm run test:regression
```

**结果与复跑方法已经保存，后续优化可直接比较同机基线。** 原始数据位于 `performance-results/latest.json`，第一次独立测量位于 `performance-results/initial-baseline.json`，真实只读观测位于 `live-metadata.json` 和 `live-runtime.json`，回归日志也在此目录。该目录被 Git 忽略，报告及脚本纳入代码审查。

- 复跑参数：`KANBAN_BENCH_SIZES=50,200,1000`、`KANBAN_BENCH_SAMPLES=15`、`KANBAN_BENCH_OUTPUT=performance-results/baseline.json`。
- 比较约束：相同机器、窗口、任务规模、动画偏好与采样数，单独运行性能测试；固定毫秒数不作为跨机器门禁。
- 落地顺序：先 formatter 与每卡一次格式化，再测收益并跑完整回归；然后分别处理局部更新和折叠延迟创建，避免同时重写渲染与状态同步。
